## 1. Animation (verdict: every animated output FAILS the standards)
Root cause, confirmed from the frames and the project format: **"Animate Sprite" applies procedural 2D transforms to one flat image.** It uses per-column displacement (fish), translation (dash/bob), rigid rotation (death), vertical squash (dragon flap), 90° rotation and mirroring (directions), and white fill (hurt). It never segments the sprite into parts, has no rig, and has no depth. The `.acestudio` format only stores raster cels with offsets. The flap took about 2 ms, which is consistent with a transform rather than generation.

| Asset | Key defects (frame-referenced) | Verdict |
|---|---|---|
| Dragon flap (benchmark `original/optimised_flap.gif`) | Wings squashed vertically together. Head and neck lost in optimised F4. Head squashed under the wings in original F4. No far-wing foreshortening or phase offset. Ping-pong with only 5 unique poses. Area CV 23% (limit 8%). The benchmark's own checker reported "0 issues". | FAIL |
| Fish swim8 (8 dirs × idle/swim/dash/hurt/death) | Swim is a vertical column-shift of one still, so the tail beat is in the wrong plane. Fins never move. Dash is a translation. Death is a rigid rotation. The 8 directions are exact rotations and mirrors of the side view (s = e rotated 90°, 0.000 diff), so there are no real top-down views and no turn animation. | FAIL |
| Fish pack (24 humanoid actions on a fish) | attack1 F45–46 collapses the body and removes the dorsal fin (area CV 21.7%). Walk F10 is a white silhouette. Loop seams fail on dodge 2.48, cast 1.76 and idle 1.55. Part count changes in 6 actions. Facing direction is inconsistent with swim8. | FAIL |
| Campfire (8 frames) | One swaying cone, with no splitting or merging. Dark streak artefacts in F0, F3 and F6. Flame tip clipped at row 0 in every frame. Embers last a single frame. Logs flicker (109–145 px change per frame) while the stones stay static. | FAIL |
| Knight sample idle | Byte-identical cels moved by 1 px, so the feet sink into the ground. | FAIL (feet, pelvis) |
| AI pose pipeline (`data\ai\anim\…`) | 6 OpenPose maps and no rendered frames. Pose 0 is nearly identical to pose 3. | Not checkable |

**Implication:** dragon, fish, fire and walk cannot be fixed by tuning parameters. They need new architecture: part segmentation with occlusion inpainting, a 2D/2.5D rig with z-ordered parts, species motion modules, and a procedural effects core. Those are roadmap phases 2–4.

## 2. AI inference and resources (measured, from the 11-03 and 11-04 benchmarks plus logs)
| Metric | 1024² "original" | 512² "optimised" |
|---|---|---|
| Warm total (median) | 23.4–29.0 s | 9.8–18.3 s |
| Diffusion | ~15 s (3.7 s/step, 4 steps, fp8, model offload) | ~8.4 s (2.1 s/step) |
| Background cut-out | 8.0–12.5 s, of which 7–10 s is **rebuilding the BiRefNet ONNX session every job** | 1.05 s once the session is cached (11-04) |
| Cold model load | 32–34 s | 20–21 s |
| VRAM peak (device) | **8.00 / 8 GB** (torch itself 4.4–4.6 GB) | — |
| System RAM peak (cold) | **31.5 / 31.5 GB** | — |
| GPU utilisation | 15–61% | — |

Ranked bottlenecks:
1. Cold load loads full-precision weights and then casts them, exhausting RAM.
2. The ORT session is rebuilt every job, because the uncapped arena forces its release.
3. Steps are overhead-bound: 4× fewer pixels gives only 1.8× speed, likely from per-forward fp8 cast plus offload transfers and VRAM saturation.
4. No idle unload; warm RSS is 11–12 GB.
5. OOM is not retried.
6. Smaller items: no fp16-fix VAE, synchronous preview writes, per-tile `.cpu()` in upscale.

Code line references point at the 0.8.1 copy. The 0.10.0 worker adds `klein.py` (FLUX.2 Klein 4B), `resources.py` and `metrics.py`, and must be re-checked against these findings before changing anything.

Cloud feasibility: the worker core runs unchanged in a Linux CUDA container. It is not network-ready: it uses stdio JSON-RPC, has no auth, takes absolute local paths, and runs one job at a time. Recommended design: an authenticated HTTPS gateway sidecar that sandboxes inputs per job and rewrites paths, with runtime_install and model_download disabled remotely. No provider was priced or contacted.

## 3. Security and privacy
| ID | Sev | Finding |
|---|---|---|
| SEC-001 | High (policy) | 0.10.0 has a **14-day trial plus licence-key gate**: after about 2026-11-15, save and export are blocked (offline Ed25519 key check; trial start stored in the registry and in `trial.json`). This conflicts with the brief's "no licence key, personal use" and would lock you out of your own work. **Your decision.** |
| SEC-002 | Medium | Requirements are pinned only at the top level, with no hashes. The torch install mixes `--index-url` and `--extra-index-url`, which creates a dependency-confusion risk. |
| SEC-003 | Medium | `model_download.py` does not enforce the URL scheme (http/file accepted). sha256 is optional, and there is a trust-on-first-use path. |
| SEC-004 | Low–Med (inferred) | Auth headers may follow cross-host redirects. |
| SEC-005 | Low | The worker trusts every job path. Confinement depends entirely on the host. |
| SEC-006 | Low (inferred) | The MCP HTTP mode token is optional. When given, it can be passed on the command line, where other processes can see it. |
| SEC-007 | Low/unknown | The MCP bridge named pipe (`acestudio-bridge-<user>`) has a predictable name and an unverified ACL. |
| SEC-008 | Info | Logs contain full user-profile paths. No secrets were found. |

Verified good:
- The worker has no sockets (stdio only).
- `torch.load(weights_only=True)` is used. There is no pickle, eval or `trust_remote_code`.
- No `shell=True`.
- safetensors are enforced.
- The catalog uses HTTPS, pinned revisions and SHA-256 for all 30 files.
- ORT and HF telemetry are off.
- No analytics or crash SDKs.
- No account.
- No silent uploads were seen.

Not checked: runtime sockets, the Lua sandbox, the pipe ACL, Authenticode, pip-audit, and the new 0.10.0 worker files line by line.
